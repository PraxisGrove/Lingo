# Lingo 实施路线

实施采用可独立验收的垂直切片。每一阶段都从真实入口走到可观察结果，不先铺设无人调用的抽象层。

## 当前交付目标：可靠的浏览器翻译插件

Lingo 以网页双语阅读和日常文本翻译为当前阶段目标，独立设计产品、交互与代码。按自身支持场景和验收结果描述能力，不以与其他产品的功能条目比较作为完成标准。

当前插件阶段包含：网页手动/自动翻译、动态内容、开放 Shadow DOM、长段落、服务配置、缓存、取消与恢复、站点规则、划词、显式悬停段落翻译、输入确认与撤销、页面侧边面板和独立文本翻译页。

| 阶段 | 范围 | 验收 |
| --- | --- | --- |
| 当前：插件功能与可靠性 | 上述核心网页与文本交互；签名规则订阅；跨会话请求控制 | 模型与契约测试、Chromium/Firefox 页面行为、安装后的 Chromium 扩展流程；发布前补充真实服务及真实站点验收 |
| 后续：文档阅读 | PDF、EPUB、扫描件 OCR 与导出 | 根据具体服务方案和样本确定结构、质量与成本标准 |
| 后续：字幕与图片 | 视频字幕、图片及漫画文字识别与翻译 | 明确数据流向、延迟、阅读顺序和费用控制 |
| 后续：平台与可选服务 | Safari、移动端、开源同步与基础托管服务 | 各平台独立验收；服务成本和隐私边界单独说明 |

后续场景暂不阻塞插件阶段交付。客户端功能开源；服务调用成本单独说明。没有预设免费接口、官方社区规则地址或托管后端。

参考开源项目只用于研究行为与模块边界，保持独立实现。判断质量应围绕真实用户任务、页面恢复、等待时间和调用成本，不能以测试数量替代实际使用结论。

当前已决定先完成本地服务契约与扩展验收；真实账户实测仍等待有效服务配置，不将本地模拟结果写成线上质量结论。

## 当前实现与验收范围（2026-10-09）

- 手动/自动翻译应用站点正文、界面与排除选择器；十类代表性布局在 Chromium/Firefox 中运行回归测试。
- 后台逐批发送结果，页面在其他批次仍等待时呈现已完成译文，弹窗命令不阻塞停止操作。
- 内联代码以不含代码正文的占位符参与翻译，响应标记校验后从本地恢复；代码块和其他受保护区域仍排除。
- 原文更新只检查受影响区域，拒绝旧段落结果；SPA 通过浏览器导航事件按 frame 更新会话。
- 安装后的 Chromium 扩展通过真实 popup、内容脚本、后台和本地 HTTP 服务验收，覆盖 iframe、取消、慢请求、工作线程重启与持久页面生命周期事件。
- 超时会中止网络请求；阻塞性服务错误停止后续批次；服务配置变化使缓存身份失效。

这些验收不依赖个人浏览器配置文件或付费账户。站点样本为可复现的本地布局，不等同于每个站点的所有线上页面均已通过。

新增插件功能：

- 划词按钮/右键/快捷键、显式悬停段落翻译、页面侧边面板与独立文本翻译页。
- 普通文本输入与 textarea 的翻译预览、确认写回、撤销；等待期间改动不会被覆盖。富文本编辑器和敏感字段不支持。
- 嵌套开放 Shadow DOM、动态根发现、宿主继承排除、根内样式与恢复；封闭根不支持。
- 超长段落按预算分段，格式标记在边界闭合与重开，完整校验后重组；失败不展示残缺段落。
- 单后台实例共享并发限制、请求启动间隔和相同批次的进行中请求；读者取消互相独立。
- 可配置 HTTPS 规则订阅与可信发布者公钥；下载限时限量，签名失败保留已验证规则，关闭更新后不下载。

当前自动化验收通过 243 项模型/契约测试、36 项 Chromium/Firefox 页面测试、8 项安装后 Chromium 扩展测试；规则签名发布脚本使用临时密钥验证。

发布前仍需真实服务质量与账户限制实测、Firefox/Edge 安装验收、至少 20 个真实站点的行为验收与长页面性能基准。自动化结果与线上结果分别记录；当前没有真实账户结论。以下历史阶段保留基础工程范围。

## 阶段 0：产品化基础

- 更新包名、manifest、图标占位和 README。
- 加入标准 AGPL-3.0 文本、CLA 与贡献说明，法律文本发布前审阅。
- 建立隐私政策、权限说明和安全报告流程。
- 将现有 settings 模型升级为带 schema 版本的最小偏好模型。

验证：`pnpm compile`、`pnpm test`、`pnpm check`、Chrome/Firefox 构建均通过。

## 阶段 1：第一条端到端翻译

- 建立 Page Translation 和 Translation Orchestrator 两个 Interface。
- 内容脚本识别静态测试页的普通段落并插入译文。
- 后台通过长连接接收翻译单元，使用内存 Provider Adapter 返回结果。
- popup 支持翻译、双语对照和显示原文。

验证：一个静态文章页可以翻译并无损恢复；页面和内容脚本均无法读取测试凭据。

## 阶段 2：真实服务与首次配置

- 实现服务配置档案、凭据存储和连接测试。
- 先完成 OpenAI-compatible Adapter，再依次加入 DeepL、Google Cloud 和 Azure。
- 完成目标语言、源语言自动/手动选择与首次配置流程。
- 增加厂商契约 fixture 和错误分类。

验证：四类服务通过同一 Orchestrator Interface 工作，UI 不包含厂商分支逻辑。

## 阶段 3：可靠的页面翻译

- 实现三层内容分类和受保护内容排除。
- 保留 inline 标记、链接与强调格式。
- 支持双语对照、仅显示译文和显示原文。
- 增加 MutationObserver、IntersectionObserver 和页面 revision。
- 实现视口优先与立即翻译到底部。

验证：静态文章、无限滚动、SPA 和 iframe fixture 不重复计费，停止后无 Lingo 残留 DOM。

## 阶段 4：编排、缓存与恢复

- 实现 IndexedDB 缓存、容量管理和失效规则。
- 实现批量、并发、超时、退避、取消和局部失败。
- 完成暂停原因、失败段落重试和显式备用服务链。
- 验证后台服务工作线程重启后的重连行为。

验证：认证失败、限流、部分响应、断连和取消都有确定结果，原文始终可恢复。

## 阶段 5：自动翻译与站点规则

- 实现全局、站点和当前页面偏好解析。
- 支持站点三态策略、源语言策略和默认自动站点。
- 建立声明式规则 schema、内置规则和用户规则编辑/导入导出。
- 建立社区规则的签名、静态分发、last-known-good 和关闭更新能力。

验证：规则优先级、签名失败、离线启动和用户覆盖均有自动化测试。

## 阶段 6：AI 质量能力

- 实现有限相邻上下文和稳定段落编号协议。
- 实现术语表、翻译指令、内置模板及版本化缓存失效。
- 支持厂商原生 glossary；其他厂商通过请求约束实现，不做译后字符串替换。
- 增加结构化输出修复与逐段结果校验。

验证：混合语言、缺失段落、顺序错乱、术语冲突和长文本拆分都有固定 fixture。

## 阶段 7：完整首版交互

- 完成 popup 当前页控制中心和 options 管理界面。
- 加入快捷键、右键菜单和默认关闭的悬浮球。
- 展示缓存占用、权限、数据流向和脱敏诊断导出。
- 完成无服务、无权限、余额不足和不支持页面的空状态。

验证：键盘可达、屏幕阅读器标签、浅色/深色主题和窄弹窗均通过检查。

## 阶段 8：跨浏览器发布

- 在 Chrome、Edge 和 Firefox 执行统一验收套件。
- 审查 manifest 权限、远程规则、CSP、可复现构建和商店披露。
- 对长页面和动态页面做 CPU、内存、DOM 增长和请求数量基准。
- 生成商店包、隐私说明、权限说明和发布清单。

验证：三个目标浏览器满足产品方案的首版成功标准，CI 产物可复现。

## 可选服务与运营路线

文档、字幕、图片、Safari、移动端和同步按后续产品需求推进。另按服务方案与验证结果评估可选的 Lingo 托管模型、官方同步实例、账户与支付、企业受管策略及运维支持。

后续能力不得改变 Community 全功能开源、BYOK 完整可用和托管服务可自建的承诺。
