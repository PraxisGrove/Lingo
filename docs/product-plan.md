# Lingo 产品方案

## 产品定位

Lingo 是面向网页阅读与日常跨语言交流的开源双语阅读与翻译插件。产品、代码、界面、文案、素材和站点规则均围绕 Lingo 的目标独立设计与实现。

当前阶段聚焦可靠的网页双语阅读、划词与段落翻译、输入辅助和独立文本翻译。PDF、EPUB、视频字幕、图片与更多平台是后续产品方向，暂不影响插件阶段交付。

按可验收阶段交付，不将尚未实现的目标写成已具备能力。当前实现状态与下一阶段验收见实施路线。

## 目标用户

### 普通读者

希望安装后即可完成基础翻译，并稳定阅读网页、文档和视频。当前基础阶段需要自行配置服务；后续面向普通用户的服务方案可以提供无需自行申请 API 密钥的基础使用路径，并清楚说明服务接收方、可用范围与成本。

### BYOK 用户

已经拥有第三方 API、OpenAI-compatible 端点或本地模型，希望完整控制服务、模型、成本与数据流向。

### 企业

需要批准服务商、私有端点、集中规则、受管部署、团队术语表、支持与 SLA，同时要求网页内容只进入获准的翻译服务。

## 产品原则

1. **原文优先**：失败、暂停或切换状态都不能破坏原网页。
2. **用户选择数据去向**：默认不跨厂商回退，不暗中改变服务商。
3. **完整开源**：不为本地功能解锁收费，只为模型额度、托管、运维和人工服务收费。
4. **安装权限透明**：全站权限只用于识别与呈现翻译，不收集浏览历史。
5. **渐进处理**：默认按阅读位置翻译，兼顾首屏速度、费用和限流。
6. **自主设计**：产品能力、交互、视觉和规则都从 Lingo 的用户需求与技术约束出发。

## 核心体验

### 首次配置

1. 选择目标语言，源语言默认自动检测。
2. 明确选择可用的基础服务，或创建自带凭据的服务配置档案。当前实现仅支持后者。
3. 使用固定示例文本测试连接，不发送当前网页。
4. 查看服务计费说明与数据流向。
5. 在示例页面确认双语显示效果。

用户可以跳过配置；没有可用服务时，翻译入口只引导配置，不静默选择其他服务。

### 翻译当前网页

1. 用户点击弹窗主按钮、快捷键或右键菜单。
2. Lingo 解析当前页面的语言、站点规则和内容区域。
3. 当前视口与临近内容优先进入翻译队列。
4. 译文逐段出现；新增正文随翻译会话持续处理。
5. 用户可切换双语对照、仅显示译文或显示原文。

### 自动翻译

- 站点翻译策略为：跟随默认、始终翻译、永不翻译。
- 支持源语言翻译策略和可编辑的默认自动站点。
- 优先级为当前页面选择、站点规则、全局偏好、自动检测。
- 用户规则高于社区规则，社区规则高于内置通用规则。

### 内容范围

- **主要内容**默认翻译。
- **页面界面**由用户选择是否翻译。
- **受保护内容**不进入普通网页翻译。
- 广告不翻译；代码块不翻译；输入框只通过独立的显式操作处理。
- 密码、支付、编辑器和 `translate="no"` 区域始终排除。

### 翻译质量

- 普通机器翻译按厂商能力批量发送独立段落。
- AI 翻译使用页面标题和有限相邻上下文，逐段返回结果。
- 用户可维护全局或站点术语表。
- 用户可选择或编辑翻译指令，内部结构化返回协议不可删除。
- 本地缓存按原文、语言、服务、模型和关键参数隔离。

### 失败与恢复

- 原文始终可见且可恢复。
- 段落独立处于等待、翻译中、成功或失败状态。
- 支持只重试失败段落。
- 认证、余额和全局限流错误暂停队列，并在弹窗说明原因。
- 只有用户明确配置备用服务链后，才允许跨厂商回退。

### 阅读与写作交互

- 划词翻译、段落悬停翻译、独立翻译窗与快捷键（页面翻译可在浏览器中配置，文本操作当前采用固定组合）。
- 输入框翻译由用户明确触发，支持确认写回与恢复原文；不会因普通网页翻译而扫描编辑区。
- 首次使用、服务切换、权限不足、失败重试与自动翻译策略都能在界面中完成。

### 后续探索：文档、视频与图片

- PDF 双语阅读与导出，保留排版；扫描件由明确选择的 OCR 能力处理。
- EPUB 双语阅读与导出，保持章节结构和链接。
- 视频字幕双语显示，支持时间轴、动态字幕、字幕文件导入导出；缺少字幕时使用明确选择的语音识别能力。
- 网页及本地图片、漫画的文字识别、翻译与结果呈现。
- 各场景共享服务配置、术语与翻译指令，同时具备独立的取消、恢复和费用控制。

## 产品入口

- **弹窗**：当前页状态、翻译主按钮、显示模式、语言、服务、站点策略和进度。
- **设置页**：服务配置档案、凭据、自动翻译、站点规则、术语表、翻译指令、缓存、权限与隐私。
- **快捷键与右键菜单**：翻译/显示原文和全文翻译。
- **悬浮球**：首版支持但默认关闭，只承载高频页面操作。

## 插件阶段范围

### 包含

- Chrome、Edge、Firefox 桌面版。
- 四类翻译服务与多个服务配置档案。
- 手动、站点和源语言自动翻译。
- 动态页面、视口优先和全文翻译。
- 三种显示状态与三层内容模型。
- 分层站点规则、签名社区更新和用户覆盖。
- 有限 AI 上下文、术语表、翻译指令和模板。
- 本地缓存、局部失败、重试和显式备用服务链。
- 首次配置、连接测试、快捷键、右键菜单和悬浮球。
- 无账户 Community 使用方式和默认零遥测。
- 划词、悬停、输入框、独立文本翻译页与页面侧边翻译面板。

### 后续方向

- 普通用户无需自行申请密钥的基础服务路径，需先确定成本和数据流向。
- PDF、EPUB、视频字幕、图片和漫画翻译。
- Safari、移动端阅读与开源配置同步。

当前阶段不承诺这些场景的交付时间，也不将尚未实现的能力宣传为现有功能。

### 阶段边界

当前基础阶段仍遵循 ADR-0014 的服务方直连与 BYOK 边界。安装即用路径的服务选择、成本和数据流向需要在实现前记录具体方案；产品规划不意味着已存在免费额度或托管后端。

后续客户端场景根据用户需求和验证结果逐步推进。账户、支付与官方托管实例保持可选，不成为使用完整开源客户端的前提。

## 商业模式

- Community 提供全部客户端功能和 BYOK 能力，采用 AGPL-3.0。
- Lingo 托管模型按额度或订阅收费，提供安装即用体验。
- 官方同步实例收费，但客户端和服务端代码开源并允许自建。
- 企业收入来自托管、部署、定制、培训、合规材料和 SLA。
- 厂商合作必须透明、非排他，并给用户明确利益。
- OEM 可以购买商业许可证；外部贡献通过 CLA 支持双重许可。

## 插件验收标准

- 支持的新闻、文档和社区站点能稳定完成翻译、切换和恢复原文。
- 动态新增段落不会重复翻译，页面内部导航不会遗留错误译文。
- 任一厂商失败不会破坏页面或泄漏凭据。
- 默认模式只翻译视口附近内容，全文模式可以稳定完成长页面。
- Chrome、Edge 和 Firefox 通过相同的行为验收套件。
- 发布包不包含遥测端点、远程代码或未声明的数据流。
- 建立至少 20 个真实目标站点的验收清单，覆盖新闻、技术文档、社区、搜索和购物，记录漏译、误译范围、排版破坏、重复请求与恢复问题。
- 对相同原文、服务和模型评测译文质量、首屏等待、调用次数与费用；不能用测试数量代替日常可用性结论。
- 首次配置、划词、段落翻译、独立文本翻译、输入确认写回与撤销都有可重复的用户场景验收。
- 对外声明支持的平台和场景通过完整扩展或应用验收；真实页面结果与本地 fixture 结果分别记录。
- 用户在声明支持的核心场景中能够持续使用 Lingo 完成任务；使用中的缺口必须公开记录并持续改善。
